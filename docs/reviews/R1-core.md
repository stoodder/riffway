# R1 — Wave 1 core logic review (judge, practice, DSP, engine, difficulty, hand position)

Independent adversarial review of `src/core/judge/`, `src/core/practice/`, `src/core/dsp/`,
`src/audio/engine/`, `src/core/difficulty/`, `src/core/handpos/` and their tests against
`docs/spec.md`, `TASKS.md` (T-013…T-016), `docs/timing.md`, `docs/game-mechanics.md`,
`docs/difficulty.md`, `docs/audio-input.md`, `docs/research/learning.md`.

## Summary
All 321 node tests in scope pass. Each module holds up well on its own: the DSP is allocation-free
and accurate, the clock round trip is exact, and the scoring and practice maths match the docs. The
serious defects are at the **judge ↔ real transport seam**. The judge tests drive a single-anchor
`TestClock`, never the real `TransportCore`. With the real transport:

- every loop pass after the first is scored all-Miss for 1-bar loops, and for 2-bar loops below 60% speed;
- the last notes before loop B are silently never judged (several seconds' worth when the tab is hidden);
- onsets played while paused are scored against the upcoming note.

I wrote throwaway scratch tests that drive `TransportCore` and `createJudge` together the way the docs
describe (a `loop-wrap` handler calls `startPass`, `advance(inputHorizon(...))` runs every 5 ms, and a
perfect player's onsets arrive 90 ms late). They reproduce findings 01–04.

Counts: **critical 1 · high 2 · medium 2 · low 5** (one low is unverified).
