# R2 review: runtime integration

Date: 2026-11-19. Reviewer: an independent subagent that did not write this code. Scope: `src/game/`,
`src/audio/` (engine, guide, backing, input, monitor, calibration, worklets), `src/app/`,
`src/ui/screens/game`, `src/ui/panels/{practice,mixer,calibration}`, `src/test-hooks/`. Out of scope:
`src/core/dsp` (being changed by another agent) and `e2e/`.

## Summary
The timing core holds up under live tests. I built the app into a scratch directory, ran it with a
throwaway data dir and drove it with Playwright (fake media, `?e2e=1`). These checks passed:
- **Keyboard timing.** Synthetic keydowns fired at the heard note time land at mean Δ +0.6 ms (all
  Perfect). Keys fired 60 ms late land at +60 ms (Great). So the heard-domain mapping is correct and
  no offset is applied twice or with the wrong sign.
- **Transport controls.** Pause/resume (with count-in), a backward seek, and a bar-aligned 70% speed
  change mid-song all stay 100% Perfect.
- **Speed trainer.** A section loop at 70% steps to 75% and then 80% after clean passes.
- **Sample-rate change mid-run.** I forced one through an input re-open. The game pauses, resumes
  with a count-in, and every later note is Perfect.
- **Saving.** A run is saved exactly once, with its best in speed bucket 110, and its practice time
  is recorded.
- **Leaks.** Three in-app visits to the game left no leaked rAF loops, intervals or AudioContexts.

The real problems are in how the parts work together:
- An abandoned game load tears down the *next* game's shared guide synth. The next game then has no
  guide audio and cannot change speed.
- A loop change can silently drop a pending bar-aligned speed change.
- Loop passes record the wrong speed for mastery.
- Nothing reacts when the guitar disappears or the context stops.
- A focused slider swallows the lane keys.
